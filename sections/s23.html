OOP koncepti se u intervjuima pitaju u teoriji, ali za QA automation inzenjera vaznije je gde se svakodnevno koriste u Page Object Model-u i test framework-u.

23.1 Class i Object

ClassNacrt koji definise properties i metode — npr. LoginPage klasa definise lokatore i akcije forme za prijavu.
ObjectInstanca klase sa konkretnim podacima — new LoginPage(driver) je jedan konkretan objekat vezan za trenutni WebDriver.
ConstructorSpecijalna metoda pozvana pri kreiranju objekta — inicijalizuje stanje (npr. prima IWebDriver i inicijalizuje lokatore preko Page Factory-ja).

23.2 Cetiri stuba OOP-a

PrincipObjasnjenjePrimer iz automatizacije
EncapsulationSakrivanje internih detalja, izlaganje samo javnog interfejsa.Page Object skriva lokatore (private) i izlaze samo metode kao Login(user, pass) — test ne zna kako je login implementiran, samo poziva metodu.
InheritanceChild klasa nasledjuje ponasanje parent klase.Sve Page klase nasledjuju BasePage koja ima zajednicke metode (WaitForPageLoad, GetTitle, Screenshot).
PolymorphismIsti interfejs, razlicito ponasanje u zavisnosti od konkretne klase.Tenant-specific override klasa (GuiCustomizationLayer) redefinise metodu iz generickog GuiLayer-a za konkretnog klijenta.
AbstractionSakrivanje kompleksnosti iza jednostavnog interfejsa.Test poziva SeleniumBlock.Execute(action) bez da zna za retry logiku, stale element handling i logovanje ispod.

23.3 Method overloading vs. overriding

// Overloading — isto ime, razliciti parametri (compile-time, u istoj klasi)
public void FillForm(string name) { ... }
public void FillForm(string name, string email) { ... }

// Overriding — child klasa redefinise metodu parent-a (runtime, virtual/override)
public class BasePage
{
    public virtual void WaitForPageLoad() { /* generic wait */ }
}
public class MaterialPage : BasePage
{
    public override void WaitForPageLoad()
    {
        base.WaitForPageLoad();
        // + cekanje na DevExpress grid da zavrsi render
    }
}
U intervjuu je cesta zamka mesati overloading i overriding — overloading je ista klasa/razliciti parametri, overriding je child/parent i zahteva virtual/override (ili abstract) kljucne reci u C#.

23.4 Interface vs. Abstract klasa

InterfaceSamo ugovor (metode/properties bez implementacije, C# 8+ dozvoljava default implementaciju). Klasa moze implementirati vise interfejsa. Nema stanja (fields).
Abstract klasaMoze imati i implementirane i apstraktne metode, i stanje (fields). Klasa moze naslediti samo JEDNU abstract klasu.
// Selenium je izgradjen na interfejsima — ovo koristis svaki dan i ne primecujes
IWebDriver driver = new ChromeDriver();   // IWebDriver je interfejs, ChromeDriver implementacija
IWebElement el = driver.FindElement(By.Id("btn"));  // isto - IWebElement

// Zasto je ovo bitno za testove: mozes da napises kod protiv interfejsa IWebDriver
// i promenis implementaciju (Chrome -> Edge -> RemoteWebDriver za Grid) bez izmene testa

// Abstract klasa u frameworku — BasePage nosi zajednicko stanje i delimicnu implementaciju
public abstract class BasePage
{
    protected IWebDriver Driver;
    protected BasePage(IWebDriver driver) => Driver = driver;
    public abstract bool IsLoaded();       // svaka Page MORA implementirati
    public virtual void WaitForPageLoad() { /* default, moze se override-ovati */ }
}
Pravilo palca: interface kad definises "sta neko moze da radi" bez zajednickog stanja (npr. IRetryable, ITestDataProvider); abstract klasa kad postoji zajednicko stanje i delimicna implementacija koju dele svi naslednici (kao BasePage).

23.5 SOLID principi — sa primerima iz test frameworka

PrincipObjasnjenjePrimer iz automatizacije
S — Single ResponsibilityKlasa ima jedan razlog da se menja.Page Object samo enkapsulira UI interakcije stranice — ne sadrzi i assertion logiku i test podatke i reporting.
O — Open/ClosedOtvoreno za prosirenje, zatvoreno za izmenu.Novi tip lokatora ili nov browser se dodaje kroz novu implementaciju interfejsa, ne izmenom postojeceg DriverFactory koda.
L — Liskov SubstitutionChild klasa mora moci da zameni parent bez da pokvari ponasanje.Ako MaterialPage : BasePage override-uje WaitForPageLoad(), i dalje mora da zadovolji ugovor (stranica MORA biti ucitana kad metoda zavrsi).
I — Interface SegregationManji, specificni interfejsi umesto jednog velikog.IRetryable i ILoggable odvojeno, umesto jednog ITestHelper interfejsa sa 20 metoda koje vecina implementacija ne koristi.
D — Dependency InversionZavisi od apstrakcije (interfejsa), ne konkretne implementacije.Page konstruktor prima IWebDriver (ne ChromeDriver direktno) — omogucava injektovanje mock drajvera za unit testiranje samog frameworka.

23.6 Access modifiers i enkapsulacija u C#

privateVidljivo samo unutar iste klase. Podrazumevano za lokatore u Page Object-u.
protectedVidljivo u klasi i svim naslednicima. Koristi se za deljeno stanje u BasePage (npr. protected IWebDriver Driver).
internalVidljivo unutar istog assembly-ja (projekta). Korisno za helper klase koje ne treba da budu javni API frameworka.
publicVidljivo svuda. Samo metode koje test kod treba da poziva (npr. Login(), ne pojedinacni lokatori).

23.7 Generics — jedna implementacija, vise tipova

// Bez generics-a bi trebalo pisati posebnu Wait metodu za svaki tip
public static T WaitUntil<T>(IWebDriver driver, Func<IWebDriver, T> condition, int timeoutSec = 10)
{
    var wait = new WebDriverWait(driver, TimeSpan.FromSeconds(timeoutSec));
    return wait.Until(condition);
}

// Upotreba — isti metod, razliciti povratni tipovi
var element = WaitUntil(driver, ExpectedConditions.ElementIsVisible(By.Id("btn")));
var isGone  = WaitUntil(driver, ExpectedConditions.InvisibilityOfElementLocated(By.Id("spinner")));
SelectElement.Options koji vraca List<IWebElement> (pominjano u B7 quick referenci) je generics u praksi — List<T> je generic kolekcija.

23.8 Composition over Inheritance

Duboka hijerarhija nasledjivanja (Page -> BasePage -> BaseComponent -> ...) postaje krhka kad promena u vrhu hijerarhije pokvari sve naslednike. Composition — klasa sadrzi instancu druge klase umesto da je nasledi — je fleksibilnije za deljeno ponasanje koje ne opisuje "je-vrsta-od" (is-a) odnos.

// Inheritance — MaterialPage JE VRSTA BasePage-a (ispravan is-a odnos, OK)
public class MaterialPage : BasePage { ... }

// Composition — Page NEMA is-a odnos sa "retry logikom", vec je KORISTI
public class MaterialPage
{
    private readonly RetryHelper _retry;   // composition: sadrzi, ne nasledjuje
    public MaterialPage(IWebDriver driver) => _retry = new RetryHelper(driver);

    public void ClickApprove() => _retry.Execute(() => Driver.FindElement(By.Id("approve")).Click());
}
Pravilo: nasledi kad je odnos zaista "je vrsta od" (MaterialPage je Page). Za deljeno ponasanje koje vise klasa treba (retry, logging, screenshot-on-fail) koristi composition — sprecava "God base class" koja vremenom nabubri.
