13.3 Waits — sinhronizacija sa browser-om

Thread.Sleep() nije wait strategija. Uvodi fiksna kasnjenja i cini testove sporim i nestabilnim.
Implicit WaitGlobalno podesavanje na svaki FindElement poziv. Lose — moze maskirati probleme i usporiti testove. Izbegavati.
Explicit WaitCeka na konkretan uslov za konkretan element. Preporuceni pristup.
Fluent WaitExplicit wait sa konfigurabilnim polling intervalom i ignorisanjem odredjenih exception-a.
// Explicit Wait — preporuceno
var wait = new WebDriverWait(driver, TimeSpan.FromSeconds(10));
var el = wait.Until(ExpectedConditions.ElementIsVisible(By.Id(btn)));

// Korisne ExpectedConditions metode:
//   ElementIsVisible, ElementToBeClickable, InvisibilityOfElement,
//   TextToBePresentInElement, UrlContains

13.4 Cesti exception-i i resenja

ExceptionUzrokResenje
NoSuchElementExceptionElement nije pronadjen u trenutku pretrage.Proveriti lokator. Dodati Explicit Wait.
StaleElementReferenceExceptionElement pronadjen ali DOM promenjen pre interakcije.Re-locate element. Retry logika.
ElementNotInteractableExceptionElement skriven, disabled ili prekriven.Cekati na clickability. JS executor kao fallback.
ElementClickInterceptedExceptionDrugi element prekriva ciljni (modal, overlay).Sacekati da overlay nestane. Scroll do elementa.
TimeoutExceptionExplicit Wait nije pronasao uslov u zadatom vremenu.Povecati timeout ili proveriti lokator.

13.8 Browser DevTools za QA debugging

Browser DevTools (F12) su svakodnevni alat za QA — ne samo za developere. Tri tab-a su najkorisnija za testiranje:

TabQA upotreba
NetworkPracenje HTTP zahteva: status kodovi, response body, trajanje, payload. Provera da li UI salje ispravne API pozive.
ConsoleJavaScript greske, console.log poruke, unhandled promise rejections. Cesto otkriva greske koje UI ne prikazuje.
ElementsInspekcija DOM-a, provera atributa (data-testid, aria-*), live CSS editing za reprodukciju layout bagova.

Network tab — sta QA trazi

Scenario: klik na "Save" dugme ne prikazuje gresku, ali podatak
         nije sacuvan u bazi.

DevTools → Network tab → filter: Fetch/XHR
  1. Pronaci POST/PUT zahtev koji se salje na klik
  2. Proveriti Status: 200, 201 (uspeh) ili 400, 500 (greska)
  3. Proveriti Request Payload — da li su poslati ispravni podaci
  4. Proveriti Response Body — da li server vraca ocekivani odgovor
  5. Ako nema zahteva uopste — UI bug, dugme ne triggeruje API poziv

Korisno: desni klik na zahtev → Copy as cURL → paste u terminal
         za brzu reprodukciju bez UI-ja

13.9 Alert-i, iframe-ovi i novi tabovi

Alert / Confirm / PromptDriver blokira dok se alert ne obradi — ne moze mu se pristupiti kroz normalni DOM.
IframeElementi unutar iframe-a nisu vidljivi driveru dok se eksplicitno ne prebaci kontekst.
Novi tab / prozorKlik koji otvara novi tab ne prebacuje driver automatski na njega — ostaje na originalnom handle-u.
// Alert
var alert = driver.SwitchTo().Alert();
alert.Accept();      // ili alert.Dismiss();

// Iframe — obavezno switch nazad posle rada unutra
driver.SwitchTo().Frame("frameNameOrId");
// ... rad unutar iframe-a ...
driver.SwitchTo().DefaultContent();

// Novi tab/prozor — window handles
var originalHandle = driver.CurrentWindowHandle;
driver.FindElement(By.Id("openInNewTab")).Click();
var newHandle = driver.WindowHandles.Except(new[] { originalHandle }).Single();
driver.SwitchTo().Window(newHandle);
// ... rad u novom tabu ...
driver.Close();
driver.SwitchTo().Window(originalHandle);
Cest uzrok NoSuchElementException-a: element realno postoji na strani, ali se trazi izvan aktivnog iframe/window konteksta. Prva provera pri debugovanju — u kom frame-u/handle-u driver trenutno "gleda".

13.10 JavaScriptExecutor — kad Selenium API nije dovoljan

var js = (IJavaScriptExecutor)driver;

// Klik kad standardni .Click() ne radi (element prekriven, ali "logicki" klikabilan)
js.ExecuteScript("arguments[0].click();", element);

// Scroll do elementa pre interakcije
js.ExecuteScript("arguments[0].scrollIntoView(true);", element);

// Citanje vrednosti koju Selenium API ne izlaze direktno
var scrollHeight = js.ExecuteScript("return document.body.scrollHeight;");

// Postavljanje vrednosti direktno u DOM (zaobilazi validaciju - koristiti oprezno)
js.ExecuteScript("arguments[0].value = arguments[1];", inputElement, "test-value");
JS klik je fallback, ne prvi izbor — zaobilazi realnu korisnicku interakciju (ne testira da li je element STVARNO klikabilan za covjeka). Koristiti samo kad je element funkcionalno klikabilan ali ga prekriva overlay koji standardni .Click() pogresno detektuje kao blokirajuci (cesta situacija sa DevExpress komponentama).

13.11 Cookies

driver.Manage().Cookies.AddCookie(new Cookie("session_id", "abc123"));
var cookie = driver.Manage().Cookies.GetCookieNamed("session_id");
driver.Manage().Cookies.DeleteCookieNamed("session_id");
driver.Manage().Cookies.DeleteAllCookies();

// Cest use-case: preskociti login flow ubacivanjem vec validnog session cookie-ja
driver.Navigate().GoToUrl(baseUrl);         // prvo mora posetiti domen
driver.Manage().Cookies.AddCookie(sessionCookie);
driver.Navigate().Refresh();                // refresh da app prepozna cookie
Ubacivanje session cookie-ja umesto UI login-a na pocetku svakog testa moze znacajno ubrzati suite — ali nosi rizik da test vise ne pokriva sam login flow, pa se zadrzava barem par dedikovanih login testova koji i dalje idu kroz UI.
