15.1 Sta je CI/CD i uloga QA-a

CI (Continuous Integration) je praksa automatskog build-ovanja i testiranja koda pri svakom commit-u. CD (Continuous Delivery) prosiruje CI automatskim deploy-om na visa okruzenja.

QA uloga: automatizovani testovi su gatekeeper koji sprecava isporuku defektnog koda. Svaki failovani test blokira pipeline.

15.2 Tipicna struktura CI/CD pipeline-a

Code Commit (git push / PR)
       |
  [1] Build       — kompajliranje, dependency restore
  [2] Unit Tests  — brzi, izolovani. Fail -> pipeline staje.
  [3] Static Analysis — linting, code coverage threshold
  [4] Deploy na Test okruzenje
  [5] Integration Tests — API, DB integracija
  [6] E2E / UI Tests   — Selenium, kriticni happy path scenariji
  [7] Deploy na Staging
  [8] Smoke Tests na Staging
  [9] Deploy na Produkciju
  [10] Smoke Tests na Produkciji

15.3 Azure DevOps YAML pipeline — Selenium C# primer

trigger:
  branches:
    include: [ main, develop ]

pool:
  vmImage: windows-latest

steps:
- script: dotnet restore
- script: dotnet build --configuration Release
- script: |
    dotnet test --configuration Release
             --logger trx
             --results-directory $(Agent.TempDirectory)/TestResults
  env:
    BASE_URL:  $(STAGING_URL)
    HEADLESS:  true

- task: PublishTestResults@2
  condition: always()
  inputs:
    testResultsFormat: VSTest
    testResultsFiles: $(Agent.TempDirectory)/TestResults/*.trx

15.4 Secrets i environment variables

# Lose — hardkodovano u YAML-u
env:
  DB_PASSWORD: MySecret123

# Dobro — secret variable iz pipeline settings
env:
  DB_PASSWORD: $(db-password)   # Secret u ADO Variable Groups
  BASE_URL:    $(staging-url)   # Moze se razlikovati po okruzenju

# Variable Groups: kreira se jednom, referencira u vise pipeline-ova
# Secret variables su enkriptovane i ne prikazuju se u logovima

15.5 Best practices za testove u CI/CD-u

  • Testovi moraju biti deterministicki — isti ulaz, isti rezultat uvek.
  • Paralelizacija: grupisati testove da se izvrsavaju paralelno.
  • Flaky testovi moraju biti izolovani i oznaceni, ne ignorisani.
  • Koristiti headless mode za browser testove u CI.
  • Cuvati screenshots i logove samo za failovane testove.
  • Retry logika samo za infrastrukturne greske, ne za legitimne failove.
