Lose:

Dobro:
  'Sistem je stabilan i spreman za release uz jedan rizik koji
   zahteva vasu odluku: postoje 2 Minor defekta na checkout stranici
   koji se javljaju samo na Safari browser-u (3% nasih korisnika).

Princip: QA daje cinjenice + preporuku + opcije. Stakeholder donosi odluku.

9.6 JIRA — defect tracking i sprint workflow

JIRA je najrasprostranjeni alat za bug tracking i Agile project management. Za razliku od Azure DevOps Test Plans (9.5), JIRA se koristi primarno za defect tracking i sprint upravljanje, ne za izvrsavanje testova.

JIRA konceptOpis
Issue TypesBug, Story, Task, Epic, Sub-task. QA najcesce kreira Bug i Sub-task za test aktivnosti.
WorkflowOpen → In Progress → In Review → Done. Custom workflow za bugove: Open → Assigned → Fixed → Ready for Retest → Closed/Reopened.
Sprint BoardKanban ili Scrum board — vizuelni pregled statusa svih issue-a u sprintu.
Filters / JQLJIRA Query Language za precizno filtriranje: project = PLM AND type = Bug AND status = Open AND priority = High
Labels / ComponentsOrganizacija po modulu, tipu testiranja ili release-u za lakse filtriranje i izvestavanje.
DashboardsCustom dashboardi sa gadgetima: bug trend, open vs closed, distribution po severity-ju.

QA workflow u JIRA sprintu

Sprint pocetak:
  1. QA review-uje stories u backlogu → dodaje AC i test notes
  2. Story prelazi u In Progress → QA priprema TC-ove

Tokom sprinta:
  3. Dev zavrsi story → QA dobija za testiranje
  4. QA testira → Pass: story → Done
                → Fail: kreira Bug, linkuje sa Story
  5. Dev fixuje bug → QA retestira → Close ili Reopen

Sprint kraj:
  6. QA proverava da svi linkovi Bug↔Story postoje
  7. Dashboard review sa PM-om: open bugs, escaped defects

Korisni JQL upiti za QA

-- Svi otvoreni bagovi u trenutnom sprintu
project = PLM AND type = Bug AND sprint in openSprints()
  AND status != Closed

-- Bagovi koje sam ja prijavio, a nisu fixovani
reporter = currentUser() AND type = Bug
  AND status NOT IN (Closed, Done)

-- Critical/Blocker bagovi koji cekaju retest
type = Bug AND priority IN (Critical, Blocker)
  AND status = "Ready for Retest"

-- Defect leakage — bagovi nadjeni na produkciji
type = Bug AND labels = production-found
  AND createdDate >= startOfMonth()
JIRA i Azure DevOps nisu medjusobno iskljucivi — na nekim projektima JIRA sluzi za defect tracking dok Azure DevOps drzi pipeline i test plans.
