16.1 Komponente robustnog test framework-a

KomponentaOpis
Driver ManagementCentralizovana inicijalizacija i teardown WebDriver-a. DriverFactory.
Page Objects (POM)Enkapsulacija UI lokatorima i interakcija po stranicama.
Base Test ClassZajednicki setUp/tearDown, driver inicijalizacija, logging.
Configuration LayerUpravljanje okruzenjima (URL, credentials) via config fajlovi ili environment variables.
Test Data ManagementSeparacija test podataka od test logike. JSON, CSV, Database ili builder pattern.
Utility / Helper LayerReusable metode: screenshot, JS executor, file reader, waits.
ReportingAllure ili ExtentReports — screenshots za failove, step-by-step log.
LoggingNLog, log4net — tracing toka testa za debugging.

16.3 Data-driven testing — xUnit primeri

[Theory]
[InlineData("user@test.com", "Test1234!", true)]
[InlineData("invalid@test.com", "Wrong", false)]
[InlineData("", "Test1234!", false)]
public void Login_WithCredentials_ReturnsExpectedResult(
    string email, string password, bool expectedSuccess)
{
 var result = new LoginPage(Driver).LoginAs(email, password);
 Assert.Equal(expectedSuccess, result.IsSuccessful);
}

16.6 Pre-commit checklist za automatizovani test

  • Test ima jasan naziv po konvenciji (Method_State_Expected).
  • Testuje tacno jednu stvar.
  • Nezavistan od redosleda izvrsavanja i od stanja koje ostavljaju drugi testovi.
  • Koristi Explicit Wait, ne Thread.Sleep().
  • Lokatori su stabilni (data-testid, ID, CSS — ne pun XPath sa indeksima).
  • Test podaci su parametrizovani, ne hard-coded u kodu.
  • Test prolazi lokalno i u CI okruzenju.
