10.1 Test environment vs. produkcija

AspektTest okruzenjeProdukcija
PodaciSinteticki ili anonimizovaniRealni korisnici
KonfiguracijaMoze se razlikovatiReferentna tacka
DostupnostMoze biti nestabilno24/7
VerzijaRC build koji se testiraPoslednji stabilni release
IntegracijeMock servisi ili sandboxRealni external servisi
Tipicna hijerarhija okruzenja:

  [Dev]  ->  [Test/QA]  ->  [Staging]  ->  [Production]

10.2 Test data management strategije

StrategijaOpisNapomena
Static test dataUnapred pripremljeni, fiksni podaci.Brzi za upotrebu. Mogu postati zaprljani.
Generated (on-the-fly)Podaci se kreiraju neposredno pre testa i brisu nakon.Svaki test ima sveze, izolovan set podataka.
Anonymized prod dataKopija produkcijskih podataka sa uklonjenjem PII.Najrealisticniji podaci, zahteva GDPR compliance.
External sourcesJSON/CSV fajlovi, Excel, baza podataka.Korisno za data-driven testiranje.

10.3 Dependency management — mock servisi i stubovi

Vecina modernih aplikacija zavisi od eksternih servisa: payment gateway, email servis, SMS provajder, third-party API.

PristupOpis
Sandbox / test modeProvajder nudi posebno okruzenje (Stripe, PayPal, Twilio). Ponasanje je identicno produkciji, ali nema realnih transakcija.
Mock servisInterni servis koji simulira ponasanje eksternog. Potpuna kontrola — simulirati 500 gresku, timeout, spor odgovor.
WireMock / MockServerAlati za kreiranje HTTP mock servera. Definisu se request/response parovi u JSON konfiguraciji.
Strategija: Unit/Integration = mock sve; System testing = sandbox provajdera; UAT/pre-prod = realne integracije sa test nalozima.

10.4 PII i GDPR u test podacima

  • Nikad ne kopirati produkcijske podatke bez anonimizacije.
  • Test emailovi uvek na domenu koji ne postoji u produkciji (npr. @test.internal).
  • Kartice — koristiti test brojeve koje payment provajder daje za sandbox.
  • Koristiti Faker biblioteke za generisanje realisticnih ali laznih podataka.

10.5 Environment checklist — pre pocetka testiranja

  [ ] Build je deployovan i verzija je verifikovana
  [ ] Seed data je prisutna i ispravna
  [ ] External mock servisi / sandbox su dostupni
  [ ] Test nalozi postoje i pristupni podaci su ispravni
  [ ] Baza podataka je u ocekivanom stanju (nije zaprljana)
  [ ] Konfiguracija okruzenja odgovara ocekivanoj (env vars, feature flags)
  [ ] Smoke test okruzenja prolazi pre pocetka punog test run-a
  [ ] Monitoring i logovi su dostupni za debugging

MajorZnacajna funkcionalnost ostecena. Workaround postoji ali je neudoban.Znacajna funkcionalnost ostecena
MinorManja funkcionalnost ostecena. Prihvatljiv workaround postoji.Manja funkcionalnost, postoji workaround
TrivialEstetski problem — UI, tekst, formatiranje. Nema funkcionalnog uticaja.Estetski problem, bez funkcionalnog uticaja

HTTP status kodovi

200 OKUspesno obradjen zahtev. Vraca se za GET i za akcije koje ne kreiraju resurs.Uspesno
201 CreatedResurs je kreiran. Vraca se za uspesni POST. Obicno ukljucuje Location header.Resurs kreiran (POST)
401Token nedostaje ili je neispravan. Klijent treba da se autentifikuje.Nedostaje token
403Autentifikacija je ok, ali korisnik nema prava na ovaj resurs.Token validan, nema dozvolu
404Resurs ne postoji na ovoj URL-i.Resurs ne postoji
422Format zahteva je ok, ali semanticki nije validan (narusena biznis pravila).Semanticki nevalidan zahtev
500Greska na serveru. Uvek je defekt — developer mora da je ispravi.Greska na serveru — uvek defekt

NotInteractableElement postoji ali je skriven, disabled ili prekriven drugim elementom.Cekati na clickability

Smoke / Sanity / Regression

SmokeBroad + Shallow. Pokrece se na svakom novom build-u. Go/No-Go odluka za dalji QA.Broad + Shallow · svaki build
SanityNarrow + Deep. Pokrece se nakon specificnog bugfix-a ili nove funkcionalnosti.Narrow + Deep · nakon fix-a
RegressionBroad + Deep. Pokrece se pre svakog release-a. Pokriva ceo scope.Broad + Deep · pre release-a
RetestingPonovo se izvrsava konkretan TC koji je prethodno failovao, nakon bugfix-a.Konkretan TC koji je failovao
