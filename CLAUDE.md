# QA Referentni Dokument — Project Context

## Working Guidelines (general, apply to all work on this project)

1. **Think before coding** — don't assume silently. If there's ambiguity or multiple valid
   readings of a request, surface them and ask instead of silently picking one.
2. **Simplicity first** — minimal code/content that solves the actual problem. No speculative
   abstractions, no "flexibility" that wasn't asked for. This is a personal reference site, not a
   product — resist the urge to over-engineer the build tooling.
3. **Surgical changes** — touch only what you must. Don't restyle or "improve" neighboring
   sections while editing one topic; don't touch the original design without being asked.
4. **Targeted execution with verification** — after any content or build-script change, actually
   run the build and click through the result (nav, search, bookmarks, theme toggle) before
   calling it done — this is a browser doc, "looks right in the source" isn't verification.

## Project Goal

A personal QA/test-automation reference document (Serbian language, ekavica) covering manual
testing (Deo I, 10 topics) and automation (Deo II, 10 topics: C#/Selenium/API/CI-CD/Appium/
AI-testing) — written to match Uros's real day-to-day work (see "User" below) so it doubles as
active interview/refresher study material, not generic textbook content.

**Current state:** a single self-contained file, `QA_Referentni_Dokument.html` (dark theme,
sidebar nav, search, bookmarks, reading-progress tracking — all client-side JS/CSS inline).

**Agreed direction (proposed, not yet implemented as of 2026-07-30):** restructure into a small
multi-page static site built from per-topic source files, and publish it to GitHub Pages so it's
reachable from any browser/device without opening a local file — no more emailing/copying the HTML
file around.

## Tech Stack (target architecture)

- Plain HTML/CSS/JS, no framework, no npm dependencies — `build.js` uses only Node's built-in
  APIs (Node v24 available locally).
- Hosting: GitHub Pages, public repo `qa-reference` on the `Bera23` GitHub account (`gh` CLI
  already authenticated locally) → `https://bera23.github.io/qa-reference/`.

## Project Structure (target — not yet built)

```
sections/*.html      — one content partial per topic (20 total, matches data/sections.json)
data/sections.json   — id, title, icon, deo (I/II), read-time metadata per topic
template.html         — shared page shell (sidebar/topbar), content placeholder
assets/style.css, assets/script.js  — shared styling/behavior across all generated pages
build.js              — Node script: sections/ + data + template -> dist/
dist/                 — build output; this is what gets pushed and served by GitHub Pages
```

## Commands

- `node build.js` — regenerates `dist/` from `sections/` + `data/sections.json` + `template.html`.
  Run after every content edit, before committing.
- Open `dist/index.html` directly in a browser to preview — no dev server needed.
- No test suite / linter for this project. Verification = build succeeds + manual click-through
  of nav/search/bookmarks/theme toggle/prev-next on a couple of generated pages before pushing.

## Workflow Preferences (this project specifically)

- No standing auto-push permission — confirm before `git push` each time (standard default
  caution; nothing project-specific overrides it here).
- Edit content in `sections/*.html` (the source), never hand-edit files under `dist/` directly —
  they're regenerated by `build.js` and any manual edit there is silently overwritten by the next
  build.

## Code Conventions

- Document CONTENT (headings, body text, table cells, code-sample comments inside the QA
  material) is in Serbian (ekavica) — deliberate, this is study material for a Serbian speaker.
- Build tooling (`build.js`) and any JS/CSS logic: code and comments in English, standard
  convention.
- Keep the existing visual design (dark theme, sidebar, table/code-block styling) — this project
  is a STRUCTURAL redesign (single file → multi-page), not a visual one. Don't restyle without
  being asked.
