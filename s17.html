17.1 Tipovi performance testiranja

TipDefinicijaKada koristiti
Load testingSistem se testira na ocekivanom normalnom opterecenju.Redovno, pre svakog release-a.
Stress testingSistem se gura iznad kapaciteta da bi se videlo kako puca i kako se oporavlja.Kada treba utvrditi tacku loma sistema.
Spike testingNagli kratki skok opterecenja (flash sale, viralni content).Ocekivani nagli rast korisnika.
Endurance/SoakSistem se drzi pod normalnim opterecenjem duzi period — trazi memory leak-ove i degradaciju performansi.Detektovanje degradacije tokom vremena.

17.2 Kljucne metrike

MetrikaOpis
Response TimeVreme od zahteva do prvog byte-a odgovora (TTFB).
ThroughputBroj zahteva koje sistem obradjuje u jedinici vremena (req/s).
Error RateProcenat failovanih zahteva. Cilj: < 1%.
Percentili (p95, p99)95% i 99% zahteva se obradjuje za manje od X ms. Bolji od proseka.
Concurrent UsersBroj simultanih korisnika koje sistem moze da podnese.

17.3 k6 — moderni load testing alat

import http from 'k6/http';
import { check, sleep } from 'k6';

export const options = {
  stages: [
    { duration: '2m', target: 100 },  // ramp up
    { duration: '5m', target: 100 },  // stay at 100 users
    { duration: '2m', target: 0 },    // ramp down
  ],
  thresholds: {
    http_req_duration: ['p(95)<2000'],  // 95% pod 2s
    http_req_failed:   ['rate<0.01'],   // error rate < 1%
  },
};

export default function () {
  const res = http.get('https://api.myapp.com/users');
  check(res, { 'status is 200': (r) => r.status === 200 });
  sleep(1);
}

17.5 QA uloga u performance testiranju

  • Definisanje realisticnih SLA sa stakeholderima pre testiranja.
  • Kreiranje reprezentativnih load scenarija — ne samo 'svi rade isti zahtev'.
  • Analiza rezultata: identifikovanje bottleneck-a (DB, API, mreza, memorija).
  • Baseline testing: merenje pre i posle svake relevantne izmene.
  • Performance regression u CI/CD-u sa failure thresholds.
