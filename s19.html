19.1 Kako AI menja QA

OblastOpis
Generisanje test case-ovaAI analizira specifikaciju ili user story i predlaze test case-ove, posebno edge case-ove koje je lako propustiti.
Vizuelna regresijaAI poredi screenshotove i detektuje vizuelne promene (Applitools, Percy).
Generisanje test podatakaLLM-ovi generisu realisticne, raznovrsne test podatke za data-driven scenarije.
Analiza defekataAI analizira log fajlove, stack trace-ove i sugerise root cause.
Odrzavanje lokatorimaHealenium automatski azurira lokatore kada se UI promeni.

19.2 LLM za generisanje Selenium C# test skripti

Primer prompta:

  'Ti si senior QA automation inzenjer koji pise Selenium C# testove.
   Koristi NUnit, Page Object Model i FluentAssertions.
   Generiši test klasu za sledeci scenario:

   Feature:  Forgot Password funkcionalnost
   URL:      /forgot-password
   Elementi: input[name=email], button[type=submit], .success-message

   Scenariji:
   1. Validan email -> prikazuje se success poruka
   2. Nevalidan email format -> prikazuje se validaciona greska
   3. Nepostojeci email -> prikazuje se ista success poruka (security by design)

   Koristi BasePage sa WaitForVisible metodom.
   Naming konvencija: MethodName_StateUnderTest_ExpectedBehavior'

Workflow:
  LLM generise skelet -> QA proverava lokatore -> QA dodaje specificne
  test podatke -> QA verifikuje Expected Result-e -> QA pokrecepokalno.
LLM stedi 60-70% vremena na boilerplate kodu. Ostatak — domain znanje, specificnosti aplikacije, edge case-ovi — ostaje iskljucivo odgovornost QA inzenjera.

19.3 Vizuelna regresija

Applitools EyesAI-powered vizuelni testing. Koristi ML da razlikuje significantne vizuelne promene od nebitnih (anti-aliasing, font rendering razlike). Integracija sa Selenium, Cypress, Playwright.
Percy (BrowserStack)Vizuelna regresija integrisana sa CI/CD pipeline-om. Svaki PR dobija vizuelni diff review.

19.4 Granice i rizici AI u testiranju

RizikObjasnjenje
HallucinationLLM-ovi mogu generisati plausibilne ali pogresne test case-ove ili nepostojece API endpoint-e. Uvek review-ovati output.
Nedostatak kontekstaAI ne zna biznis pravila, istoriju projekta ni specificnosti sistema.
False confidenceVizuelni AI alati mogu propustiti relevantne promene ili prijaviti lazne pozitive.
OdgovornostAI generisani test case-ovi su QA odgovornost. Nema opravdanja 'AI je to generisao'.

19.5 Generisanje Selenium C# koda

// LLM generisani skelet — potrebna QA revizija
public class ForgotPasswordPage : BasePage
{
 private By EmailField   => By.CssSelector(input[name=email]);
 private By SubmitButton => By.CssSelector(button[type=submit]);
 private By SuccessMsg  => By.CssSelector(.success-message);

    [Test]
    public void ValidEmail_ShouldShowSuccessMessage()
    {
 var page = new ForgotPasswordPage(Driver);
 page.Navigate();
 page.EnterEmail(user@test.com);  // QA dodaje: konkretni test email
 page.Submit();
 Assert.That(page.GetSuccessMessage(), Does.Contain(Check your email));
    }
}

Severity nivoi

BlockerSistem se ne moze koristiti. Testiranje je blokirano. Nema workaround-a.Sistem ne radi, nema workaround-a
CriticalKriticna funkcionalnost je slomljena. Korisnik ne moze da dovrsi kljucni task.Kriticna funkcionalnost slomljena
MajorZnacajna funkcionalnost ostecena. Workaround postoji ali je neudoban.Znacajna funkcionalnost ostecena
MinorManja funkcionalnost ostecena. Prihvatljiv workaround postoji.Manja funkcionalnost, postoji workaround
TrivialEstetski problem — UI, tekst, formatiranje. Nema funkcionalnog uticaja.Estetski problem, bez funkcionalnog uticaja

HTTP status kodovi

200 OKUspesno obradjen zahtev. Vraca se za GET i za akcije koje ne kreiraju resurs.Uspesno
201 CreatedResurs je kreiran. Vraca se za uspesni POST. Obicno ukljucuje Location header.Resurs kreiran (POST)
401Token nedostaje ili je neispravan. Klijent treba da se autentifikuje.Nedostaje token
403Autentifikacija je ok, ali korisnik nema prava na ovaj resurs.Token validan, nema dozvolu
404Resurs ne postoji na ovoj URL-i.Resurs ne postoji
422Format zahteva je ok, ali semanticki nije validan (narusena biznis pravila).Semanticki nevalidan zahtev
500Greska na serveru. Uvek je defekt — developer mora da je ispravi.Greska na serveru — uvek defekt

Selenium exception-i

NoSuchElementElement nije pronadjen u DOM-u. Proveriti lokator i dodati Explicit Wait.Proveriti lokator + dodati Wait
StaleElementElement pronadjen ali DOM se promenio pre interakcije. Re-locate element.Re-locate element
NotInteractableElement postoji ali je skriven, disabled ili prekriven drugim elementom.Cekati na clickability
ClickInterceptedDrugi element (modal, overlay) prekriva ciljni element pri kliku.Sacekati da overlay nestane
TimeoutExplicit Wait nije pronasao ocekivani uslov u zadatom vremenskom okviru.Povecati timeout / proveriti lokator

Smoke / Sanity / Regression

SmokeBroad + Shallow. Pokrece se na svakom novom build-u. Go/No-Go odluka za dalji QA.Broad + Shallow · svaki build
SanityNarrow + Deep. Pokrece se nakon specificnog bugfix-a ili nove funkcionalnosti.Narrow + Deep · nakon fix-a
RegressionBroad + Deep. Pokrece se pre svakog release-a. Pokriva ceo scope.Broad + Deep · pre release-a
RetestingPonovo se izvrsava konkretan TC koji je prethodno failovao, nakon bugfix-a.Konkretan TC koji je failovao
