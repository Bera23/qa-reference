19.1 Komponente robustnog test framework-a

KomponentaOpis
Driver ManagementCentralizovana inicijalizacija i teardown WebDriver-a. DriverFactory.
Page Objects (POM)Enkapsulacija UI lokatorima i interakcija po stranicama.
Base Test ClassZajednicki setUp/tearDown, driver inicijalizacija, logging.

Test Data ManagementSeparacija test podataka od test logike. JSON, CSV, Database ili builder pattern.

19.3 Data-driven testing — xUnit primeri

[Theory]
[InlineData("user@test.com", "Test1234!", true)]
[InlineData("invalid@test.com", "Wrong", false)]
[InlineData("", "Test1234!", false)]
public void Login_WithCredentials_ReturnsExpectedResult(
    string email, string password, bool expectedSuccess)
{
 var result = new LoginPage(Driver).LoginAs(email, password);
 Assert.Equal(expectedSuccess, result.IsSuccessful);
}

19.6 Pre-commit checklist za automatizovani test

  • Test ima jasan naziv po konvenciji (Method_State_Expected).
  • Testuje tacno jednu stvar.
  • Nezavistan od redosleda izvrsavanja i od stanja koje ostavljaju drugi testovi.
  • Koristi Explicit Wait, ne Thread.Sleep().
  • Lokatori su stabilni (data-testid, ID, CSS — ne pun XPath sa indeksima).
  • Test podaci su parametrizovani, ne hard-coded u kodu.
  • Test prolazi lokalno i u CI okruzenju.

19.7 Logging strategija

NivoKada koristiti
Trace/DebugDetaljan tok izvrsavanja (koji lokator se trazi, koji retry pokusaj) — ukljuceno samo lokalno ili kad se istrazuje konkretan fail, previse "sum" za normalan CI log.
InfoVisok nivo koraka testa (test pocinje, test zavrsen, glavna akcija izvrsena) — ono sto ostaje ukljuceno u CI da bi log bio citljiv bez preplavljivanja.
WarningNesto neocekivano ali test je nastavio (npr. retry je bio potreban, fallback logika aktivirana) — signal da nesto vredi istraziti iako test nije pao.
ErrorTest je pao ili je exception uhvacen. Uvek uz kontekst — koji korak, koji podatak, screenshot ako je moguce.
// Prazan catch blok NIKAD ne sme ostati bez loga — ako se greska guta necujno,
// sledeci fail na istom mestu je nemoguce dijagnostikovati unazad
try
{
    element.Click();
}
catch (ElementClickInterceptedException ex)
{
    TestLog.Assert.Trace(TraceMode.Warning, $"Klik presretnut, pokusavam JS fallback: {ex.Message}");
    js.ExecuteScript("arguments[0].click();", element);
}
Korelacija: dobar log ukljucuje test ime i identifikator podatka (npr. SpecId) u svakoj liniji, ne samo poruku — kad 200 testova pise u isti nightly log, "Element not found" bez konteksta je beskorisno; "Element not found [MaterialTests.EditSpec, SpecId=SPEC-TEST-001]" nije.
