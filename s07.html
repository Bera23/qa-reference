7.1 Test strategija vs. Test plan

Test strategijaDokument visokog nivoa koji definise KAKO organizacija pristupa testiranju uopste. Pise se jednom. Autor: QA Lead.
Test planDokument nizeg nivoa koji definise STA, KO, KADA i KAKO se testira za konkretan release. Pise se za svaki release. Autor: QA inzenjer.

7.2 Test plan — IEEE 829 struktura

SekcijaSadrzaj
1. Test Plan IDJedinstven identifikator dokumenta i verzija.
2. IntroductionSvrha, scope i referentni dokumenti.
3. Test ItemsSta se testira — feature-i, moduli, build verzija.
4. Features to TestKonkretne funkcionalnosti u scope-u.
5. Features Not to TestEksplicitno isljucene oblasti i razlog — jednako vazno kao scope.
6. ApproachTehnika testiranja, tipovi testova, nivo automatizacije.
7. Entry/Exit CriteriaUslovi pocetka i zavrsetka testiranja za ovaj ciklus.
8. Test DeliverablesArtefakti: test case-ovi, izvestaji, defect log.
9. Testing TasksKonkretne aktivnosti, ko je odgovoran, redosled.
10. Environmental NeedsOkruzenja, podaci, alati, pristup, mock servisi.
11. ResponsibilitiesRACI matrica.
12. ScheduleVremenski plan — milestone-i i trajanje svake faze.
13. Risks & MitigationPotencijalni rizici i planovi za ublazavanje.

7.3 Risk-based testing

Risk Score = Probability of Failure x Business Impact

  Visok rizik   ->  testirati prvo i najdetaljnije
  Srednji rizik ->  standardna pokrivenost
  Nizak rizik   ->  smoke level ili izostaviti

Faktori visokog rizika:
  - Novi ili znacajno izmenjeni moduli
  - Kriticna funkcionalna oblast (payment, auth, data migration)
  - Oblasti sa istorijski visokim brojem defekata
  - Kod bez code review-a ili unit testova

7.4 Test estimation — tehnike

Work Breakdown Structure (WBS)

  Pisanje test case-ova:     8h
  Priprema test podataka:    2h
  Setup okruzenja:           1h
  Manuelno izvrsavanje:     16h
  Regression:                4h
  Defect reporting/retest:   3h
  ----------------------------
  Ukupno:                   34h

Three-Point Estimation

Expected = (O + 4M + P) / 6
  O = Optimistic  |  M = Most likely  |  P = Pessimistic

  Primer: O=3h, M=5h, P=10h  ->  Expected = 5.5h

Uvek ukljuciti: review TC-ova, retest nakon bugfix-ova,
regression, buffer za okruzenje (min 10-20%).

CoverageKoji zahtevi su pokriveni, koji nisu i zasto. RTM status.

   Regression suite: 100% pass.
   QA preporuka: GO za release uz monitoring deferred defekata.'
