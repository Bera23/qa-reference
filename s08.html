8.1 QA uloga u svakom delu sprinta

Sprint FazaQA Aktivnost
Sprint RefinementPostavljanje pitanja koja developer i PO nisu postavili: edge case-ovi, ponasanje pri gresakama external API-ja. Shift-left u praksi.
Sprint PlanningReview user story-ja: da li je story testabilan, da li AC postoje i da li su precizni. Procena QA effort-a za sprint.
DevelopmentParalelno pisanje test case-ova. Priprema test podataka. Setup ili verifikacija test okruzenja.
TestingManuelno izvrsavanje TC-ova. Exploratory testiranje. Prijava defekata. Retest. Regression.
Sprint ReviewVerifikacija acceptance criteria zajedno sa PO-om. QA verifikuje da ono sto je prikazano zaista radi.
RetrospectiveSta je blokiralo testiranje, gde smo imali defect leakage, sta treba promeniti u procesu.

8.2 Definition of Done (DoD)

Primer DoD stavki relevantnih za QA:

  [ ] Svi acceptance criteria su ispunjeni i verifikovani od strane QA
  [ ] Test case-ovi su napisani i odobreni
  [ ] Sve High i Critical severity greske su zatvorene
  [ ] Regression suite prolazi bez novih gresaka
  [ ] Funkcionalnost je testirana na staging okruzenju
  [ ] API kontrakt je verifikovan (ako postoji API promena)

8.3 Definition of Ready (DoR)

Primer DoR stavki relevantnih za QA:

  [ ] User story ima jasne acceptance criteria
  [ ] Acceptance criteria su testabilni (precizni, merljivi)
  [ ] UI mockup ili dizajn je dostupan (ako postoji)
  [ ] Zavisnosti su identifikovane i razresene
  [ ] Test podaci su definisani ili postoji plan za njihovu pripremu

8.4 Acceptance Criteria — pisanje i verifikacija

Lose AC:  'Korisnik moze da se uloguje u sistem.'

Dobro (Given/When/Then format):
  Given: Korisnik je na login stranici i nije ulogovan
  When:  Unese validan email i password i klikne Login
  Then:  Biva preusmerеn na /dashboard
         I header prikazuje njegovo ime
         I sesija traje 30 minuta neaktivnosti

8.5 Three Amigos sesija

Three Amigos je kratka sesija pre razvoja feature-a. Ucestvuju Product Owner (biznis), Developer (tehnika) i QA (kvalitet). Cilj: zajednicki razgovor koji otkriva nesuglasice i edge case-ove pre nego sto developer napise liniju koda.

8.6 BDD — Behavior-Driven Development

Feature: User Login

  Scenario: Successful login with valid credentials
    Given the user is on the login page
    When  the user enters email 'user@test.com'
    And   the user enters password 'Test1234!'
    Then  the user is redirected to the dashboard
    And   the header displays the user's name

  Alati: Cucumber (Java), SpecFlow (C#), Behave (Python)

⚡ Quick Reference

Severity nivoi

BlockerSistem se ne moze koristiti. Testiranje je blokirano. Nema workaround-a.Sistem ne radi, nema workaround-a
CriticalKriticna funkcionalnost je slomljena. Korisnik ne moze da dovrsi kljucni task.Kriticna funkcionalnost slomljena
MajorZnacajna funkcionalnost ostecena. Workaround postoji ali je neudoban.Znacajna funkcionalnost ostecena
MinorManja funkcionalnost ostecena. Prihvatljiv workaround postoji.Manja funkcionalnost, postoji workaround
TrivialEstetski problem — UI, tekst, formatiranje. Nema funkcionalnog uticaja.Estetski problem, bez funkcionalnog uticaja

HTTP status kodovi

200 OKUspesno obradjen zahtev. Vraca se za GET i za akcije koje ne kreiraju resurs.Uspesno
201 CreatedResurs je kreiran. Vraca se za uspesni POST. Obicno ukljucuje Location header.Resurs kreiran (POST)
401Token nedostaje ili je neispravan. Klijent treba da se autentifikuje.Nedostaje token
403Autentifikacija je ok, ali korisnik nema prava na ovaj resurs.Token validan, nema dozvolu
404Resurs ne postoji na ovoj URL-i.Resurs ne postoji
422Format zahteva je ok, ali semanticki nije validan (narusena biznis pravila).Semanticki nevalidan zahtev
500Greska na serveru. Uvek je defekt — developer mora da je ispravi.Greska na serveru — uvek defekt

Selenium exception-i

NoSuchElementElement nije pronadjen u DOM-u. Proveriti lokator i dodati Explicit Wait.Proveriti lokator + dodati Wait
StaleElementElement pronadjen ali DOM se promenio pre interakcije. Re-locate element.Re-locate element
NotInteractableElement postoji ali je skriven, disabled ili prekriven drugim elementom.Cekati na clickability
ClickInterceptedDrugi element (modal, overlay) prekriva ciljni element pri kliku.Sacekati da overlay nestane
TimeoutExplicit Wait nije pronasao ocekivani uslov u zadatom vremenskom okviru.Povecati timeout / proveriti lokator

Smoke / Sanity / Regression

SmokeBroad + Shallow. Pokrece se na svakom novom build-u. Go/No-Go odluka za dalji QA.Broad + Shallow · svaki build
SanityNarrow + Deep. Pokrece se nakon specificnog bugfix-a ili nove funkcionalnosti.Narrow + Deep · nakon fix-a
RegressionBroad + Deep. Pokrece se pre svakog release-a. Pokriva ceo scope.Broad + Deep · pre release-a
RetestingPonovo se izvrsava konkretan TC koji je prethodno failovao, nakon bugfix-a.Konkretan TC koji je failovao
