DEO I — MANUALNO TESTIRANJE

📝 5. Pisanje test case-ova✓ Procitano

⏱ ~3 min citanja

5.1 Struktura profesionalnog test case-a

IDJedinstven identifikator (TC-001, LOGIN-TC-003). Koristiti prefiks modula.
TitleKoncizan naziv koji opisuje STA se testira i POD KOJIM USLOVOM. Ne 'Test login'.
PriorityHigh / Medium / Low — utice na redosled izvrsavanja.
PreconditionsStanje sistema, podaci i okruzenje koji moraju biti ispunjeni pre pocetka.
Test DataKonkretne vrednosti koje se koriste (email, password, iznos).
StepsNumerisani, atomski koraci — svaki korak = jedna akcija.
Expected ResultPrecizno definisano ponasanje sistema. Mora biti verifikabilno i nedvosmisleno.
Actual ResultPopunjava se tokom izvrsavanja. Prazno dok se ne izvrsi.
StatusPass / Fail / Blocked / Skipped.

5.2 Status — razlika Blocked vs Skipped

PassTest case je izvrsen i sistem se ponasa kako je definisano u Expected Result-u.
FailTest case je izvrsen i sistem se NE ponasa kako je definisano. Defekt se prijavljuje.
BlockedNije moglo da se izvrsi zbog spoljne prepreke: environment pao, blocker bug, test podaci nisu pripremljeni. Nije QA odluka.
SkippedSvesna odluka da se TC ne izvrsi: out of scope, deferred. QA ili lead donosi odluku svesno.

5.3 Title — kako pisati

Format koji uvek radi: [Akcija] + [Uslov/Ulaz] + [Ocekivani ishod].

Lose:
  'Test login'  |  'Ne radi'  |  'Problem sa formom'

Dobro:
  'Login sa validnim kredencijalima preusmjerava korisnika na dashboard'
  'Login sa pogresnim passwordom prikazuje error poruku'
  'Login sa praznim email poljem prikazuje validacionu gresku'

5.4 Happy path, edge case, negative path

Happy pathIdealni scenario, sve je validno, korisnik radi tacno ono sto se ocekuje. Mora uvek biti pokriven.
Edge caseGranicna vrednost ili ekstremni uslov koji je tehnicki validan ali neuobicajen: maksimalni unos, prazna lista, 10.000 elemenata.
Negative pathNevalidni ulazi i neocekivane akcije: pogresni tipovi podataka, nedostajuca obavezna polja, akcije bez dozvola.

5.5 Granularnost — kada deliti, kada spajati

Kada DELITI:

  • Svaki korak ima sopstveni expected result koji je bitan sam po sebi.
  • Fail jednog dela ne znaci nuzno fail celog flowa.
  • Razliciti TC-ovi imaju razlicite preconditions ili test podatke.

Kada SPAJATI:

  • Koraci su strogo sekvencijalni i bez prethodnog nema smisla testirati sledeci.
  • Radi se o end-to-end flow verifikaciji (npr. celokupan checkout proces kao smoke TC).

5.6 RTM — Requirements Traceability Matrix

RTM mapira zahteve na test case-ove i defekte. Omogucava odgovor na pitanje: 'Koji zahtevi su pokriveni testovima i koji imaju otvorene defekte?'

Zahtev ID | Opis                        | TC ID(s)       | Status      | Defekti
----------+-----------------------------+----------------+-------------+---------
REQ-001   | Korisnik moze da se uloguje | TC-001,TC-002, | In Progress | BUG-045
          |                             | TC-003,TC-004  |             |
REQ-002   | Reset passworda             | TC-010, TC-011 | Pass        | -
REQ-003   | Sesija istice nakon 30 min  | TC-015         | Blocked     | BUG-051

5.7 Primer test case-a

Title:         Login sa validnim email-om i passwordom preusmjerava na dashboard

Preconditions:
  - Aplikacija dostupna na test okruzenju
  - Postoji aktivan nalog: user@test.com / Test1234!
  - Korisnik nije ulogovan

Steps:
  1. Otvoriti login stranicu
  2. Uneti email u polje Email
  3. Uneti password u polje Password
  4. Kliknuti dugme Login

Expected Result:
  - Korisnik je preusmerеn na /dashboard
  - Header prikazuje korisnicko ime ili avatar
  - Ne prikazuje se poruka o gresci

⚡ Quick Reference

Severity nivoi

BlockerSistem se ne moze koristiti. Testiranje je blokirano. Nema workaround-a.Sistem ne radi, nema workaround-a
CriticalKriticna funkcionalnost je slomljena. Korisnik ne moze da dovrsi kljucni task.Kriticna funkcionalnost slomljena
MajorZnacajna funkcionalnost ostecena. Workaround postoji ali je neudoban.Znacajna funkcionalnost ostecena
MinorManja funkcionalnost ostecena. Prihvatljiv workaround postoji.Manja funkcionalnost, postoji workaround
TrivialEstetski problem — UI, tekst, formatiranje. Nema funkcionalnog uticaja.Estetski problem, bez funkcionalnog uticaja

HTTP status kodovi

200 OKUspesno obradjen zahtev. Vraca se za GET i za akcije koje ne kreiraju resurs.Uspesno
201 CreatedResurs je kreiran. Vraca se za uspesni POST. Obicno ukljucuje Location header.Resurs kreiran (POST)
401Token nedostaje ili je neispravan. Klijent treba da se autentifikuje.Nedostaje token
403Autentifikacija je ok, ali korisnik nema prava na ovaj resurs.Token validan, nema dozvolu
404Resurs ne postoji na ovoj URL-i.Resurs ne postoji
422Format zahteva je ok, ali semanticki nije validan (narusena biznis pravila).Semanticki nevalidan zahtev
500Greska na serveru. Uvek je defekt — developer mora da je ispravi.Greska na serveru — uvek defekt

Selenium exception-i

NoSuchElementElement nije pronadjen u DOM-u. Proveriti lokator i dodati Explicit Wait.Proveriti lokator + dodati Wait
StaleElementElement pronadjen ali DOM se promenio pre interakcije. Re-locate element.Re-locate element
NotInteractableElement postoji ali je skriven, disabled ili prekriven drugim elementom.Cekati na clickability
ClickInterceptedDrugi element (modal, overlay) prekriva ciljni element pri kliku.Sacekati da overlay nestane
TimeoutExplicit Wait nije pronasao ocekivani uslov u zadatom vremenskom okviru.Povecati timeout / proveriti lokator

Smoke / Sanity / Regression

SmokeBroad + Shallow. Pokrece se na svakom novom build-u. Go/No-Go odluka za dalji QA.Broad + Shallow · svaki build
SanityNarrow + Deep. Pokrece se nakon specificnog bugfix-a ili nove funkcionalnosti.Narrow + Deep · nakon fix-a
RegressionBroad + Deep. Pokrece se pre svakog release-a. Pokriva ceo scope.Broad + Deep · pre release-a
RetestingPonovo se izvrsava konkretan TC koji je prethodno failovao, nakon bugfix-a.Konkretan TC koji je failovao
